# Tooling & Verification Workflow

This document introduces the **skfd** (ProofScaffold) CLI toolchain and its verification capabilities. The system supports two distinct workflows for validating Metamath proofs: standard **Package Verification** for project builds and **Scatter Proof Verification** for rapid prototyping and debugging.

## 1. Overview: skfd CLI

`skfd` is the command-line interface for the Proof Scaffold, providing tools for project management, building, verification, and diagnostics.

### Key Capabilities
- **Project Management**: Initialize projects, manage dependencies.
- **Building**: Compile high-level Python/DSL proof definitions into Metamath `.mm` files.
- **Verification**: Orchestrate multiple verifiers (Python, C, Rust) to ensure correctness.
- **Diagnostics**: Provide detailed error reporting and source mapping.

## 2. Scenario A: Package Verification (Standard Flow)

This is the primary workflow for maintaining a structured Metamath project. It treats the project as a cohesive "package" with defined dependencies, source roots, and build targets.

### Initialization

Use `init-pkg` to create a new standard package structure:

```bash
$ skfd init-pkg my-logic
Initializing package 'my-logic' at .../src/my-logic...
Creating default config at .../.skfd...
Done.
```

### Structure
A typical package structure looks like this:

```text
my-logic-project/
├── .skfd              # Configuration file
├── pyproject.toml     # Python dependencies
└── src/
    └── logic/
        ├── __init__.py
        └── build.py   # Entry point exporting the HilbertSystem
```

### Configuration (`.skfd`)
The `.skfd` file defines active verifiers and project settings:

```toml
[project]
name = "my-logic"
version = "0.1.0"

[verifiers]
active = ["mmverify", "metamath-c", "knife"]
```

### Workflow
To verify the entire package:

```bash
$ skfd verify my-logic
```

**What happens behind the scenes:**
1. **Discovery**: `skfd` finds the package root and entry points.
2. **Build**: It executes the Python code (e.g., `build.py`) to generate a `LinearPlan`.
3. **Link**: The Linker resolves all symbols, imports, and exports across modules.
4. **Emit**: A single, complete `.mm` file is generated in `build_out/`.
5. **Verify**: All configured verifiers run against the generated `.mm` file.

## 3. Scenario B: Scatter Proof Verification (Ad-hoc/Scripting)

This workflow is ideal for:
- Prototyping a single lemma.
- Debugging a specific proof strategy.
- Learning and teaching (e.g., writing a script to prove `Modus Tollens`).
- Unit testing specific logic without building the whole project.

In this scenario, we bypass the heavy project structure and Linker. Instead, we manually drive the `MMBuilder` and invoke verifiers directly from a Python script.

### Initialization

Use `init-proof` to create a standalone script with all necessary boilerplate:

```bash
$ skfd init-proof my_proof.py
Creating proof script 'my_proof.py'...
Done. Run it with: skfd verify my_proof.py
```

### Workflow

You can run the script directly with Python, or use `skfd verify` as a convenient wrapper:

```bash
$ skfd verify my_proof.py
```

This command detects that the target is a file (not a package) and executes it. The script itself (generated by `init-proof`) contains a self-verification routine that:
1. Builds a temporary in-memory `.mm` file.
2. Invokes all active verifiers configured in `.skfd`.
3. Reports pass/fail status immediately.

### Helper Pattern
The generated script uses a helper pattern (similar to `manual_proofs.py`) that:
1. Takes a `HilbertSystem` and a list of `LemmaProof` objects.
2. Uses `MMBuilder` to emit them to a temporary `.mm` file.
3. Invokes `skfd.verifier.aggregate.run_all` to check them.

## 4. Verifier Management

`skfd` is designed to be verifier-agnostic. It acts as a frontend that can dispatch verification tasks to multiple backends.

### Built-in Support
- **mmverify**: A pure Python reference verifier (always available).
- **metamath-c**: The standard C `metamath` executable (requires `metamath` binary).
- **metamath-knife**: The high-performance Rust verifier (requires `metamath-knife` binary).

### CLI Commands

Manage your verifiers via the `skfd verifier` subcommand:

- **List available/active verifiers**:
  ```bash
  $ skfd verifier list
  ```

- **Add a new verifier**:
  ```bash
  $ skfd verifier add knife /path/to/metamath-knife
  ```

- **Remove a verifier**:
  ```bash
  $ skfd verifier remove old-verifier
  ```

By enabling multiple verifiers, you ensure your proofs are robust and compatible with the wider Metamath ecosystem.
