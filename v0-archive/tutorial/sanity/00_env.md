# Step 00 — Environment and Verifier Sanity

This step verifies one thing and one thing only:

> **The Metamath verifier is available, and it can successfully verify a minimal proof.**

No logic is introduced here.
No reasoning is required.
This is a pure *environment sanity check*.

If this step fails, nothing else in the tutorial will work.

---

## What This Step Checks

This sanity check confirms that:

1. A Metamath verifier (`mmverify.py`) can be executed from Python.
2. The verifier can read a database from standard input.
3. A minimal Metamath database can be extended with a generated `$p` statement.
4. The verifier exits successfully when the proof is correct.

At this stage, we do **not** care about logic, inference, or meaning.
We only care about the *mechanics*.

---

## The Metamath Fixture

**File:** `fixtures/sanity/00_env.mm`

This fixture defines the smallest self-contained Metamath world
that still allows a theorem to be verified.

It contains:

- one constant for the type (`wff`)
- one variable (`ph`)
- one typing hypothesis (`$f`)
- one trivial axiom (`$a`)

There is no proof yet — the proof will be generated by Python.

Conceptually, this database only says:

> “There exists a well-formed formula `ph`, and an axiom stating `ph → ph`.”

Nothing more.

---

## The Companion Program

**File:** `tools/sanity/check_00_env.py`

This program performs the following actions:

1. Reads the fixture database (`00_env.mm`).
2. Appends a trivial `$p` theorem that reuses the axiom.
3. Sends the resulting database to the Metamath verifier via standard input.
4. Checks that the verifier exits without error.

The program does not analyze the proof.
It does not interpret logic.
It simply ensures that the full pipeline executes successfully.

---

## How to Run This Step

From the repository root, run:

```bash
python tools/sanity/check_00_env.py --mmverify verifier/mmverify.py
```
