# ProofScaffold — Agent Guide for M1.4（Rev.2：整合 Review）

## Conservative ScopeFrames + `$c/$v` Filtering + Synthetic Origin Tagging

> 目标：把 Linker 从 M1.3 的 “DAG 可线性化”推进到 “**DAG → Stream 时，作用域纪律可强制、可诊断、可复现**”。核心是 **Stage 5: Scope planning (ScopeFrames)** 的保守基线：**每个 ProofUnit 一个 fresh `${ ... $}`**，消灭跨 unit 的隐式上下文污染。

设计依据（本指引按这些文档的约束来写）：

* 三层架构与信任边界（Python/Linker 不在 TCB）。
* Linker Model v3：Stage 5 ScopeFrames、scope balance、no leakage、以及 `$c/$v` 的合法性规则。
* Roadmap：M1.4 里程碑定位、验收方式与测试分层。
* Generator 输出边界与 ProofUnit 形态（decls_local/exports 的契约）。
* Token Layout 不变量：token 是 int、contiguous、layout-agnostic、provenance 不入 token。
* Debug Slice MVP：step_id/span、上下文摘要字段的预留方向。

---

## -1. 变更日志（Rev.2：采纳 Review 的可执行修改）

本版本相对上一版 M1.4 的关键修订：

1. **新增硬规则：过滤 `$c/$v`（ConstDecl/VarDecl）**

   * 规划 frame 时必须 **主动过滤掉** unit 内的 `ConstDecl`/`VarDecl`，绝不把 `$c/$v` emit 进 `${ ... $}`。
   * 这不是 “hoist”，而是 **Dropping（丢弃局部声明）**：假设它们要么已在全局 header/预留 prologue 处理中出现，要么由后续 M1.6 统一 hoist。
   * 这样避免 Metamath 的重复声明/冲突问题，并与 v3 “`$c/$v` 不应在嵌套 scope 中出现”的纪律一致。

2. **“Decls first, Exports last” 检查升级为 Linter Error（强制）**

   * 保持原约束，但明确：这是 **错误**（fail-fast），不是 warning；用于反向塑形 Generator。

3. **Synthetic Statement 的 Origin 语义强化**

   * `ScopeEnter/ScopeExit` 的 origin 不再只是“借用 unit.origin”，而是带 **synthetic tag / virtual_source**（例如 `virtual_source="linker:stage5"`、`note="[Synthetic: ScopeEnter]"`）。
   * 使 Debug/IDE 能一眼区分“生成器语句”与“linker 插入语句”。

4. **ScopeFramePlan 增加 `context_hash` 字段（占位但稳定）**

   * M1.4 阶段可先做 `context_hash = stable_hash(unit_id)`；后续可升级为 active context digest（`$f/$e/$d` 摘要），成为增量验证与 debug slice 的关键支点。

## 0. Milestone Definition（统一目标）

### 0.1 里程碑定义

**M1.4 = Scope Planning（保守 ScopeFrames）**

最小闭环交付：

1. 基于 M1.3 的 `units_linear_order[]` 构造线性化 emission plan
2. 对每个 ProofUnit：生成一个独立 ScopeFrame：`${ <unit-body> $}`（保守策略：一个 unit 一个 frame）
3. frame 内部顺序强制：`decls_local` 在前，`exports` 在后（违者 linter error）
4. 禁止跨 unit 的作用域借用：不得让 unit 的导出断言定义点受其他 unit 的 `$f/$e/$d` 污染（no leakage）
5. 输出必须形成 verifier 可接受的 multi-unit stream（sanity fixture 验证）

### 0.2 非目标（仍不做）

* 不做 relocation / name mangling（M1.5）
* 不做完整 `$c/$v` 两段式 emission（M1.6）
* 不做完整 interface contract extraction / `$d` 推断（Phase 3/4）

## 1. 输入与硬约束（M1.4 的安全边界）

### 1.1 输入前置假设

* 输入是 Stage 1 后的 LIR ProofUnits：tokens 已是 `SymbolRef(int)[]`，非字符串流。
* 已完成 M1.3：有 `units_linear_order[]`（确定性 topo order）。

### 1.2 `$c/$v` 的“沉默处理”改为显式规则（Review A）

**硬规则：在 M1.4 规划 unit frame 时，必须过滤掉 `ConstDecl` 与 `VarDecl`。**

* 原因：v3 已把 `$c/$v` 定位为 global header discipline（最终 stream 中不应出现在 nested scope）。即使 M1.6 才做全量 hoist，M1.4 也不能把 `$c/$v` 放进 `${...$}`，否则会踩到重复声明/冲突的 verifier 失败。
* 本里程碑采取 **Dropping**：

  * 在 frame body 遍历时直接跳过 `ConstDecl`/`VarDecl`。
  * 同时可以（建议）记录一个 `debug_event` 或 `lint_note`：“dropped local `$c/$v`”，用于排查 generator 是否仍在 unit 内吐 `$c/$v`。
* 重要说明：如果 dropping 导致最终 emitted stream 缺少必要的 `$c/$v`，verifier 会拒绝，这是正确的反馈：说明全局声明路径（或 M1.6 预留 header slot）未就绪。

### 1.3 Token layout 不变量（必须继承）

* token 运行时类型是 `int`；TokenSeq contiguous；pass 必须 layout-agnostic；provenance 不得塞进 token。

### 1.4 确定性硬约束

* frame 生成顺序完全由 `units_linear_order[]` 决定
* frame 内 statement 顺序稳定（建议：保留 generator 原始顺序；但在结构上强制 `decls_local` 段整体早于 `exports` 段）

## 3. 必须实现的 Pipeline（Stage 5：Scope planning）

### 3.1 数据模型（建议强制可序列化）

**ScopeFramePlan**（建议字段）：

* `frame_id`：稳定分配（按 topo 顺序的 index）
* `unit_id`
* `origin_ref`：指向 OriginTable（用于定位“这个 frame 属于哪个 unit”）
* `synthetic_origin_refs`：可选（用于 frame enter/exit）
* `context_hash: u64`：默认 `stable_hash(unit_id)`（占位）
* `stmts[]`：frame 内 stmt 列表（stmt_id + origin_ref + token seq 等）

**LinearPlan**：

* `prologue_stmts[]`：可空；作为 M1.6 header 的结构预留位（M1.4 不要求填充）
* `frames[]`：按 topo 顺序排列的 frame plans

> 注意：这些结构节点可以是 dataclass；但 stmt token payload 必须仍是 `TokenSeq[int]`。

---

### 3.2 规划规则：每个 unit 一个 fresh frame（含 `$c/$v` Filter Rule）

对每个 unit `U`（按 `units_linear_order[]`）：

1. 插入 `ScopeEnter`（synthetic stmt）
2. 发出 `U.decls_local`（保持 generator order）
3. 发出 `U.exports`（保持 stable order）
4. 插入 `ScopeExit`（synthetic stmt）

**新增 Filter Rule（Review A，硬规则）：**

在把 `decls_local` 和 `exports` 写入 frame 时：

* 若 stmt.kind ∈ `{ConstDecl, VarDecl}`：**直接 drop（不进入 frame）**
* 其它 stmt：正常写入 frame
* 允许（建议）在 debug 输出中记录 dropped 事件（但不要污染 token）

> rationale：v3 明确 `$c/$v` 的合法性应由 header discipline 保障，且最终 stream 不应在 nested scope 中出现 `$c/$v`。M1.4 不做 hoist，但必须避免“把 `$c/$v` 放进 `${...$}`”这种必踩坑输出。

---

### 3.3 Conformance Checks（fail-fast，带 origin）

#### 3.3.1 Scope balance（单位内自洽）

* 若 unit 自身 LIR 含嵌套 `${/$}`，必须在 unit 内闭合
* 不允许“半开 scope”跨 unit 边界
* 违者：`E_UNIT_SCOPE_IMBALANCE`（primary=触发 stmt origin；related=unit origin；origin_chain 含 stage/unit/stmt）

#### 3.3.2 `$f/$e/$d` 不得逃逸 frame

* 任何 `$f/$e/$d` 出现在 frame 外：`E_UNSCOPED_LOCAL_STMT`

#### 3.3.3 “Decls first, Exports last” 强制为 **Linter Error**（Review B）

* 检查：`exports` 必须整体出现在 `decls_local` 之后（frame 内）
* 违者：`E_EXPORT_ORDER_INVALID`（**error，不降级为 warning**）
* 目的：把 ProofUnit 形态固定为“先建立本地上下文，再定义/证明导出”，便于理解依赖与未来 contract 提取。

#### 3.3.4 `$c/$v` 被 drop 的行为必须可诊断（推荐）

* 不是错误（引导期容错），但建议输出一个结构化 note：

  * code：`N_DROPPED_LOCAL_CV_DECL`
  * primary_origin：该 stmt.origin
  * related：unit.origin
  * chain：`Stage5.ScopePlanning → FilterCV`
* 用于推动 generator 逐步停止在 unit 内吐 `$c/$v`。

## 4. Traceability（Synthetic Origin 策略强化）

### 4.1 Synthetic Statement 的 origin 语义（Review C）

对 `ScopeEnter/ScopeExit`：

* 仍然把 unit.origin 作为 **related origin**（因为 frame 是为 unit 服务）
* 但 **primary origin** 建议使用一个 synthetic origin record（如果 Origin 结构允许扩展字段）：

示例（概念）：

* `Origin(module="linker", file="<synthetic>", line=0, virtual_source="linker:stage5", note="[Synthetic: ScopeEnter]")`
* 或：在 OriginTable record 的 “extra/attrs” 中写入

  * `virtual_source="linker:stage5"`
  * `synthetic_kind="ScopeEnter"` / `"ScopeExit"`

这样 debug slice / IDE 可以明确显示“这不是 generator 产物”。

> 如果当前 OriginTable schema 暂不支持 attrs：至少要在 `origin_chain[]` 中显式标注 `synthetic(ScopeEnter)`，避免误导开发者去找“哪一行 Python 代码写了 `${`”。

## 5. Debug Slice 协同（context_hash 字段落地）

### 5.1 `context_hash`（Review D）

在 `ScopeFramePlan` 上新增：

* `context_hash: u64 = stable_hash(unit_id)`（M1.4 占位实现）

要求：

* 必须使用**稳定 hash**（不要用 Python 内置 `hash()`，它可能随进程随机化）
* 推荐：`sha256(str(unit_id)).digest()[:8]` 取 u64（或固定种子的 xxhash/siphash）
* M1.4 不要求计算 active `$f/$e/$d` 集合，但字段必须存在，为后续把 Active Context Snapshot 摘要接进 debug slice 做接口准备。

## 6. 验收标准（DoD：Rev.2）

M1.4 完成，当且仅当：

1. ✅ 每个 ProofUnit 都被包装进独立 `${ ... $}`（outer frame），顺序严格跟随 `units_linear_order[]`。
2. ✅ 无跨 unit hypothesis leakage：导出定义点不受其它 unit 的 `$f/$e/$d` 污染。
3. ✅ scope balance 可检查：unit 内 scope 不平衡在 linker 阶段 fail-fast，诊断可追责。
4. ✅ **`$c/$v` 不会出现在任何 `${ ... $}` 内的 frame body**（被过滤 drop），避免重复声明/冲突坑。
5. ✅ “Decls first, Exports last” 违背时必然报错（linter error），推动 generator 形态收敛。
6. ✅ multi-unit 输出至少一个 sanity fixture 可被 verifier 接受（闭环）。
7. ✅ Synthetic stmt 可辨识：`ScopeEnter/Exit` origin 含 synthetic tag（或 origin_chain 显式标注）。
8. ✅ `context_hash` 字段存在且稳定（同输入两次一致）。

## 7. 测试目标（Rev.2 更新版）

沿用 Roadmap 的测试分层策略。

### A. Sanity Tests

* **A0. `sanity_m14_two_unit_scoped_emission_verifies`**
  两个 unit（A→B），按 topo 顺序输出，每个 unit 一个 frame；verifier 接受。

* **A1. `sanity_m14_frame_boundaries_present`**
  每个 unit 正好一对 outer `${/$}`；frame_id/unit_id 映射稳定。

### B. Golden Tests（确定性）

* **B1. `golden_m14_linear_plan_snapshot`**
  快照 `LinearPlan`（frames + frame 内 stmt_id 列表 + synthetic 标记），两次运行 byte-identical。

* **B2. `golden_m14_context_hash_stable`**
  同输入两次构建，`context_hash` 一致（显式使用稳定 hash 算法）。

### C. Adversarial Tests（必须早失败/必须捕获泄漏）

* **C1. `adv_m14_unit_internal_scope_imbalance_rejected`**
  unit 内 `${` 未闭合/多 `$}` → `E_UNIT_SCOPE_IMBALANCE`，含 unit origin 与触发 stmt origin。

* **C2. `adv_m14_export_order_invalid_is_error`**（Rev.2 强化）
  构造 exports 混到 decls_local 前 → `E_EXPORT_ORDER_INVALID`（error）。

* **C3. `adv_m14_local_cv_decl_dropped`**（Rev.2 新增）
  unit 内包含 `ConstDecl/VarDecl`：
  断言：它们不出现在 frame body（可额外断言产生 `N_DROPPED_LOCAL_CV_DECL` note）。

* **C4. `adv_m14_ghost_context_dependency_eliminated`**
  设计一个“若不隔离会侥幸通过”的用例：M1.4 必须稳定拒绝或稳定要求显式本地声明，不能再靠前序 unit 的 active context。

### D. Structural Tests（中端不变量）

* **D1. `struct_m14_every_unit_exactly_one_outer_frame`**
* **D2. `struct_m14_no_fed_outside_frames`**：frame 外无 `$f/$e/$d`
* **D3. `struct_m14_no_cv_inside_frames`**（Rev.2 新增）：frame 内无 `ConstDecl/VarDecl`
