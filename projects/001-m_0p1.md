## 1. M0.1 的定义与“最小闭环”边界

### 1.1 目标（M0.1 只做这件事）

建立一个在 CI 里**永远可跑**、**稳定**、**可重复**的最小闭环：

> clean env → build minimal IR → linker_v1 emit → Metamath verifier accepts

这与三层架构/信任边界完全一致：Python 与 linker 不可信，**只有 verifier 的 accept/reject 是权威**。

Roadmap 对 M0.1 的交付与验收也明确如此：

### 1.2 非目标（M0.1 刻意不做）

M0.1 不实现这些（但要把“接口槽位”留好，避免未来重构）：

* 多模块依赖闭包、拓扑排序（Stage 4）
* 作用域规划（Stage 5）在多 Unit 上的复杂策略
* Token-level relocation（Stage 6）
* SourceMap 完整版（Stage 8）

**注意**：M0.1 可以只链接 *一个* unit，但数据模型必须是 v4 的那套“可扩展骨架”，否则你会在 M1.2/M1.5 再次重写。

## 2. 从 linker_v0/M1.4 失败里提炼出的 M0.1 硬约束

M0.1 需要把以下“结构性坑”直接封死（否则后面必炸）：

### 2.1 Token ID：从第一天起就是**全局 SymbolId 空间**

M1.4 最大的 P0 债之一：token id 单元本地化，导致后续 token-level relocation 必然撞车。
Link Model v4 明确要求：**Stage 1 后所有 token 必须处于单一全局 SymbolId 空间**，并且 token 运行时就是 int。

**M0.1 的做法**：即使只有一个 unit，也要用“全局 interner”分配 SymbolId；不要出现任何 per-unit symtab 的语义。

### 2.2 诊断：所有失败必须是结构化 Diagnostic

M1.4 诊断指出 `diag.details` 不可见会严重降低可调试性。
v4 规范要求：所有 linker 失败都必须是 `LinkerDiagError(diag)`，并且 `__str__` 必须包含 details 且确定性输出。

**M0.1 的做法**：哪怕只有一个 sanity test，也把 Diagnostic 结构一次性搭好。

### 2.3 决定性（Determinism）从 M0.1 开始就是 CI Gate

Roadmap 把 determinism 视为一等约束。
v4 也把“同样 IR → 同样输出/同样诊断”写成硬规则。

**M0.1 的做法**：最少加入 1 条 determinism 测试：同一 IR build 两次，输出字节级一致（或 token 级一致）。

## 3. M0.1 的逻辑依赖图（你要实现的最小骨架）

把 M0.1 看成“最小编译器工具链”：

```
Stage 0  (Front-end)  : 构造最小 ProofUnitIR（含 LIR）
Stage 1  (Resolve+Lint): 建立 SymbolTable + 校验 token/kind/reserved 等
Stage 7  (Emit)        : 生成最小 .mm 文本流
Verifier               : 运行 mmverify，要求 accept
```

其中 Stage 0 作为 Generator/DSL 的位置要清晰（将来 DSL 只是 Stage 0 的一个实现）。

## 4. 推荐的工程切分与目录（避免 v0 的“功能长在一起”）

建议直接创建全新入口 `linker_v1/`，不要在 v0 上打补丁（否则旧债会渗透到新结构里）：

```
src/proof_scaffold/linker_v1/
  api.py                  # LinkerV1.link(units) 入口
  context.py              # LinkerContext: tables, config, determinism helpers
  diag.py                 # Diagnostic + LinkerDiagError + format
  origin.py               # OriginTable + OriginRef intern
  symbols.py              # SymbolDef + SymbolInterner + checks
  ir_lir.py               # LIR stmt definitions (最小子集)
  unit.py                 # ProofUnitIR
  passes/
    stage1_resolve.py     # Stage 1 (M0.1: resolve+lint 基线)
  emit/
    emit_mm.py            # Stage 7: emit .mm (最小)
  sanity/
    check_sanity.py       # CI entrypoint (可 import + 可 CLI)
tests/
  test_m0p1_sanity.py
  test_m0p1_determinism.py
```

关键点：**diag / origin / symbols 必须从第一天独立出来**，这是后续所有阶段可扩展性的根。

## 5. M0.1 数据模型最小集（对齐 Link Model v4，但只实现必须字段）

> M0.1 的原则：**类型与不变量先对齐 v4**，再逐步补功能。

### 5.1 基本类型

* `SymbolId = int`
* `OriginRef = int`
* `UnitId = str`（确定性：如 `"sanity:unit0"`）
* `TokenSeq = list[int]`（M0.1 先用 list，后续可换 packed buffer，但 Pass 必须 layout-agnostic）

### 5.2 OriginTable（必须有）

每个 Statement、每个 Unit 都带 `origin_ref`，最小字段：

* `module_id, file, line`（测试里可用固定虚拟值）

原因：后续 SourceMap/DebugSlice/诊断链都依赖它。

### 5.3 SymbolDef + SymbolInterner（全局）

SymbolDef 最小字段：

* `id, kind(Const|Var|Label), origin_ref, local_name, origin_module_id`

Interner 以 `(origin_module_id, local_name, kind)` 为 key；M0.1 即使单 unit，也要按这个规则走，防止“未来再迁移”。

### 5.4 LIR 语句（M0.1 用到的最小子集）

建议先只支持这几种即可：

* `ConstDecl(tokens: TokenSeq)`
* `VarDecl(tokens: TokenSeq)`
* `FloatingHyp(label: SymbolId, typecode: SymbolId, var: SymbolId)`
* `Theorem(label: SymbolId, expr: TokenSeq, proof: TokenSeq)`
* 可选：`Comment(text)`
* 可选（但强烈建议留接口）：`ScopeEnter/ScopeExit`（即便 M0.1 先不需要复杂 scope）

v4 的完整 LIR 集合更大，但 M0.1 不必全做；关键是 token 都是 SymbolId（int），不是字符串。

### 5.5 ProofUnitIR（M0.1 最小）

* `unit_id`
* `origin_ref`
* `origin_module_id`
* `lir_stmts: list[LIRStmt]`
* `exports: list[SymbolId]`（M0.1 可以只导出一个 theorem label）

## 6. M0.1 的最小 Pass 合约（写在代码注释里，未来照此扩展）

### Stage 0：构造 sanity ProofUnitIR

M0.1 可以把 Stage 0 写在 `sanity/build_sanity_ir.py` 或测试里，核心是：
**生成一个 verifier 必然接受的最小 Metamath 程序**。

建议使用这个经典最小可证例子（只用一个 $f 作为证明）：

* 常量：`|-`
* 变量：`ph`
* 浮动假设：`wph $f |- ph $.`
* 定理：`th1 $p |- ph $= wph $.`

这是一个非常干净的闭环：proof 只引用自身 mandatory hyp，能把你所有“token/label/kind/emit/verifier”链路跑通。

### Stage 1：resolve + early lint（M0.1 版本）

即便单 unit，也要做这些检查（否则你在 M1.2 才补就太晚）：

* 禁止 `$` 前缀的 local_name（reserved token）
* proof token 必须都是 Label kind（这里 proof 里是 `wph`，是 label）
* expr token 必须是 Const/Var kind（`|-` 是 Const，`ph` 是 Var）
* 不允许“未定义 SymbolId”“越界 token id”这类静默 stringify（M1.4 曾有此类问题）

输出：

* `SymbolTable: dict[SymbolId, SymbolDef]`
* “已通过 lint 的 units”（可原样返回）

### Stage 7：emit（M0.1 版本）

M0.1 允许先不做 relocation（等价映射），但 emit 的接口必须未来可插 relocation table：

* `emit_name(SymbolId) -> str`：M0.1 返回 `SymbolDef.local_name`
* 输出文本 `.mm`（或 bytes）

**关于 header**：
v4 的最终形态是两段式：先 header `$c/$v` 再 body。
M0.1 为了最小可以先不实现复杂 scope，但我建议**直接实现两段式 header**，因为它极便宜，却能避免 M1.4 文档里提到的“spec/实现不一致”协调税。

最小 emitted stream（示意）：

```
$c |- $.
$v ph $.
wph $f |- ph $.
th1 $p |- ph $= wph $.
```

（如果你额外发出 `${ $}` 也可，但不是必须。）

## 7. check_sanity 的实现规范（M0.1 最关键的“钉子”）

### 7.1 形式

* `python -m proof_scaffold.linker_v1.sanity.check_sanity` 可运行
* 同时提供可 import 的函数 `run_sanity() -> None`（便于测试调用）

### 7.2 check_sanity 做什么

1. 构造 minimal IR（Stage 0）
2. 跑 linker_v1（Stage 1 → Stage 7）
3. 调用 verifier 验证 emitted `.mm`
4. 任一步失败：

   * 必须抛出 `LinkerDiagError` 或 verifier error（你可以把 verifier error 也封装成 Diagnostic）
   * 输出必须包含 origin（哪怕是 “sanity harness” 的 origin）

### 7.3 check_sanity 不做什么

* 不读取外部工程包，不走复杂 import/export
* 不引入非决定性来源（时间戳、随机数、哈希迭代顺序）

## 8. M0.1 测试用例清单（把验收标准固化成 CI）

### 8.1 `test_m0p1_sanity_smoke`

* 调 `run_sanity()`
* 断言 verifier accept（无异常）

### 8.2 `test_m0p1_determinism`

* 构造同一 IR（或调用同一 build 函数两次）
* emit 两次，断言输出 **字节级一致**
* 如果输出同时包含诊断或伴随数据，也应确保格式稳定（但 M0.1 可先只测试 emitted `.mm`）

> 这条测试是 M0.1 阶段就必须有的“地基钉”。

## 9. 如何“借鉴既有失败与测试积累”：在 M0.1 就把回归护栏立起来

你现在手里最有价值的资产不是 v0 的实现，而是：

* 已暴露的结构性失败模式（M1.4 诊断）
* v4 规范列出的必做 adversarial suite（未来 CI 的核心）

但 M0.1 不需要一次把这些 adversarial tests 全实现；正确做法是：

### 9.1 M0.1 立即落地的“前置护栏”（低成本高收益）

* **全局 SymbolInterner**：从根上消灭 “unit-local token ids” 
* **Diagnostic + details 可见**：立刻修复 “有信息但看不到” 
* **决定性测试**：输出不稳定就是失败 

### 9.2 把 v4 的 ADV 测试列表当作 M0.1 的“测试目录规划”

你可以在 `tests/adversarial/` 先放空文件与 TODO（或 xfail 标记），确保团队对“未来必须覆盖哪些坑”有共同清单：
这样迁移到 M1.x 时不会遗忘。

## 10. M0.1 完成标准（Definition of Done）

M0.1 结束时你应该能同时满足：

1. `check_sanity` 在 CI 可跑、稳定、无外部依赖波动 
2. `linker_v1` 已拥有：

   * 全局 `SymbolId` interning（即便单 unit）
   * OriginTable（每个 stmt/unit 有 origin_ref）
   * 统一 Diagnostic（details 可见、格式确定）
3. 至少两条测试：sanity smoke + determinism
4. 输出的最小 `.mm` 被 verifier 接受（闭环成立）
