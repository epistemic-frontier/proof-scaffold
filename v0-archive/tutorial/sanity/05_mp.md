# Step 05 — Modus Ponens (MP): The First Real Inference Rule

This step introduces the first *genuine* Metamath inference rule:
**modus ponens**.

At this point in the tutorial, you already know:

- a Metamath proof is a **stack program**
- `$f` hypotheses establish typing (well-formedness)
- `$e` hypotheses are **concrete stack inputs** required by a rule
- verification is done by a trusted verifier, not by Python

Now we will add one more ingredient:

> A proof can reference an assertion label (`$a` / `$p`) whose meaning depends on
> the **shape and order** of required hypotheses.

---

## 1. What Modus Ponens Means Here

In informal logic, modus ponens is:

- Given: `ph`
- Given: `(ph -> ps)`
- Conclude: `ps`

In Metamath, a rule is represented as an assertion with **essential hypotheses** (`$e`).
So we encode MP as an axiom-like assertion:

- `h1 $e wff ph $.`
- `h2 $e wff ( ph -> ps ) $.`
- `ax-mp $a wff ps $.`

Read it as:

> If the stack contains the two required hypotheses (in the required order),
> then applying `ax-mp` pops them and pushes the conclusion `ps`.

---

## 2. The Three Fixtures

This step is taught via three small `.mm` databases:

### (A) `05_mp_happy.mm` — the working case

It defines `ax-mp` and proves a theorem by using the proof tokens:

```
ph ps h1 h2 ax-mp
```

This is the minimal non-trivial proof that relies on an inference rule.

### (B) `05_mp_missing_hyp.mm` — missing required hypothesis

It tries to prove the same theorem but provides only:

```
 ph ps h1 ax-mp
```

This fails because `ax-mp` requires *two* essential hypotheses.

### (C) `05_mp_bad_proof_tokens.mm` — wrong order of hypotheses

It provides both hypotheses but in the wrong order:

```
ph ps h2 h1 ax-mp
````

This fails even though the “set” of hypotheses is the same.
Metamath is not using a derivation tree here. It is executing a stack program,
and **the order of stack items matters**.

---

## 3. What You Should Learn

After finishing this step, you should internalize three facts:

1) **Metamath proofs are stack programs.**
   Rule application consumes stack items in a fixed order.

2) **`$e` hypotheses are not informal assumptions.**
   They are required, ordered inputs to a rule.

3) **Closure edges are real.**
   When a theorem’s proof references `ax-mp`, the theorem depends on the unit
   exporting `ax-mp`. This is the first place where a linker-style dependency
   graph becomes meaningful.

---

## 4. How to Run

From repository root:

```bash
python tools/sanity/check_05_mp.py
````

Expected:

* `05_mp_happy.mm` passes verification
* the other two fixtures fail verification (with different error messages)

The failures are part of the lesson: read them carefully.
